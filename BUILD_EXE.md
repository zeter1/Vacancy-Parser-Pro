# Сборка Vacancy Parser Pro в готовый EXE

`build_exe.bat` делает полноценную Windows-сборку автоматически. Вручную устанавливать PyInstaller, `requests`, BeautifulSoup, pandas, openpyxl или настраивать виртуальное окружение не требуется.

## Быстрый способ

1. Скачайте/распакуйте репозиторий в обычную папку Windows.
2. Дважды щёлкните `build_exe.bat`.
3. Дождитесь сообщения:

```text
[OK] READY BUILD CREATED AND VERIFIED.
```

4. Готовая сборка находится в `dist/`:

```text
dist/
├─ Vacancy Parser Pro.exe
└─ icon.ico
```

При переносе программы на другой компьютер копируйте **всю папку `dist`**, чтобы `icon.ico` оставался рядом с EXE. Python на компьютере, где запускается готовый EXE, не нужен.

## Что делает BAT

Сборщик выполняет все необходимые этапы:

- находит проверенный Python 3.13;
- если Python 3.13 отсутствует, пытается установить его через Windows Package Manager (`winget`) для текущего пользователя;
- создаёт отдельное build-окружение `.build-venv`;
- устанавливает зависимости из `requirements.txt` (`requests`, BeautifulSoup, pandas, openpyxl и их зависимости);
- устанавливает проверенный PyInstaller 6.22.3 и hooks;
- выполняет `pip check`;
- компилирует исходники;
- запускает offline unit tests;
- запускает встроенный source self-test без обращения к сайтам вакансий;
- проверяет наличие `icon.ico`;
- удаляет старые `build/`, `dist/` и `.spec`;
- создаёт оконный one-file `Vacancy Parser Pro.exe`;
- автоматически копирует `icon.ico` рядом с EXE;
- запускает `--self-test` уже на собранном EXE;
- сообщает об успехе только после прохождения packaged self-test.

## Почему icon.ico лежит рядом с EXE

Приложение хранит пользовательские файлы и ищет runtime-иконку относительно каталога запущенного EXE. Поэтому BAT автоматически кладёт `icon.ico` в `dist/`. Никаких ручных копирований после сборки делать не требуется.

Сам файл EXE уже содержит icon для значка Windows; соседний `icon.ico` нужен приложению при создании окна Tkinter.

## Что проверяет self-test

`vacancy_parser.py --self-test` не ходит на реальные сайты и не запускает GUI. Он проверяет, что:

- импортируются GUI, scraper и основные Python-зависимости;
- реестр источников вакансий не пуст;
- runtime-ресурс `icon.ico` реально доступен по пути, который будет использовать упакованная программа.

Тот же тест запускается на собранном EXE, поэтому случай, когда PyInstaller создал файл, но забыл нужный ресурс, считается ошибкой сборки.

## Повторная сборка

Просто снова запустите:

```bat
build_exe.bat
```

Старый `dist/` удаляется автоматически. `.build-venv` можно оставить — это ускоряет следующую сборку. Если его удалить, BAT создаст его заново.

## Для GitHub Actions / Codex

```bat
build_exe.bat --ci
```

В этом режиме нет `pause`, а BAT возвращает корректный exit code. GitHub Actions запускает packaging только для специальных `[package]`-коммитов или вручную через `workflow_dispatch`, поэтому обычные правки README не создают тяжёлые EXE-сборки.

## Интернет при сборке и при работе

Интернет требуется во время первой сборки для установки Python/пакетов, если их ещё нет в build-env. Готовый EXE не требует Python, но самой программе интернет нужен для получения актуальных вакансий с внешних сайтов/API.

Unit/self-tests намеренно offline и не зависят от доступности Rabota.by, HH.ru, Praca.by, Belmeta или GSZ.gov.by.

## Если сборка упала

BAT останавливается на первом критичном этапе. Смотрите первое сообщение `[ERROR]` или traceback выше него.

Типовые причины:

- отсутствует `winget`, а Python 3.13 ещё не установлен;
- proxy/антивирус блокирует PyPI;
- `icon.ico` удалён из репозитория;
- папка проекта недоступна для записи;
- защитное ПО блокирует запуск только что созданного unsigned EXE.

Сборка не считается готовой только по факту появления `.exe` — обязательно должен пройти packaged self-test.

## Что можно удалить

После успешной сборки можно удалить:

```text
build/
.build-venv/
Vacancy Parser Pro.spec
```

Для запуска готовой программы оставьте содержимое `dist/`.
